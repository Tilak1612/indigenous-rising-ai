# Funding Navigator gap analysis

Brief requirement → current state → gap → decision. "Keep" means the existing
code is reused as-is; "extend" means additive change; "replace" means the
existing code is removed because it is wrong.

| # | Requirement | Current | Decision |
|---|---|---|---|
| 1 | Normalised catalogue with provider, classification, apply URL, link type, intake status, rounds, evidence, verification events | One flat `grants` table, free-text funder, homepage links, no evidence column | **Extend `grants`** additively (slug, apply_url, apply_link_type, provider_id, program_category, intake_status, opens_at, closes_at (= deadline), matching_funds, documents_required, application_steps, eligibility_exclusions, repayment_terms, entrepreneur age, business age, source_evidence jsonb, verification_confidence, schema_version). **Add** `funding_providers`, `funding_program_rounds`, `funding_verification_events`, `funding_link_checks`, `funding_review_queue`, `funding_link_reports`, `funding_outbound_clicks`. Do **not** add the 20 other tables from the brief until a feature reads them. |
| 2 | Public `/funding` with search, multi-select filters, URL state, pagination, verified-only, accepting-applications | 20-row client fetch, two single-select filters, no URL state | **Replace the list section** with PostgREST-side filtering + URL params + pagination (keep hero, alerts CTA, types section, footer). |
| 3 | `/funding/<slug>` detail pages, prerendered, in sitemap | `/funding/:id` mock page | **Replace `FundingDetail.tsx`** with a DB-backed page by slug (id still resolves and redirects). Prerender every published slug. Delete `funding-data.ts`, `FundingList.tsx`, `FundingFilters.tsx`. |
| 4 | Region / type landing pages | None | **Add** `/funding/<province-slug>` (13) + `/funding/indigenous-business-loans` + `/funding/indigenous-business-grants`, prerendered with original copy, canonical to themselves, filtered lists. |
| 5 | Official link engine: most specific verified destination, label by type, no homepage as "Apply" | Homepage as "Apply on funder's site" | **Add** `apply_link_type` (application_form, application_instructions, program_page, directory, contact) and `src/lib/funding-links.ts` that picks label + URL; audit every row's link. |
| 6 | Link health, freshness, change detection, review queue | Manual migrations | **Add** `check-funding-links` edge function (HEAD/GET with UA, respects robots-ish rate limit, records `funding_link_checks`, flips `needs_review` on 404/410/DNS; never flips on 403/429/timeout) scheduled weekly; schedule `check-funding-freshness` daily (internal email only). Review queue rows created on every automated change. |
| 7 | Dashboard: overview, discover, matches, saved, applications, deadlines, documents, assistant, profile | Matches, saved (+readiness flag), browse (paywalled), tasks, documents exist | **Extend**: un-paywall browse (free per `plans.ts`), fix its filters, add Deadlines view (verified `closes_at` + tasks), extend `funding_saved_matches.status` with the brief's stages additively, show apply link type + intake status + "not assessed" items on matches. |
| 8 | Eligibility engine returns Potential Match / Needs More Information / Likely Ineligible / Closed / Not Yet Open | yes / maybe / no from rules + LLM | **Extend** the edge function: evaluate `applicant_types`, intake status and dates in code; map to the five states; keep LLM for fit sentence only. |
| 9 | AI assistant grounded in verified records | None | **Extend `ai-assistant`**: inject up to 8 published programmes matching the user's territory with source URLs and verification dates, plus hard rules (no amounts/deadlines not in the record, always cite). |
| 10 | Admin funding management | None | **Add** `/admin` tab: table, edit, publish/unpublish, verify, review queue, link checks, reports. Admin-only RLS policies on `grants` and the new tables. |
| 11 | Email deadline alerts (30/14/7/3/1) | Digest only, no deadlines | Deferred to a follow-up PR once rounds with real `closes_at` exist; schema carries `closes_at` so the ladder has data. Documented in FUNDING_IMPLEMENTATION_PLAN. |
| 12 | Business plan integration (map requirements to plan sections) | Readiness workspace links to drafts | **Extend** the readiness workspace: seed `missing_info` items from `documents_required`. |
| 13 | Analytics (clicks, filters, saves) | GA4 events exist | **Extend**: `funding_outbound_clicks` aggregate counter (no user id) + GA4 events for filter use, detail view, official click, save. |
| 14 | Entitlements: browsing free, matching quotas unchanged | Browse paywalled in dashboard | Fix #7; no pricing or quota change. |
| 15 | Tests | 44 vitest files; guards for crawlability | **Add** unit tests for link engine, filters/URL state, status derivation; guard tests for routes/prerender/sitemap; SQL assertions documented in FUNDING_TEST_PLAN. Browser smoke via the gstack headless browser against the Vercel preview. |
| 16 | Deploy | Merge to main auto-deploys (hard stop: owner merges) | Migrations applied to production additively with **no new row published**; publication is an admin action after owner review. |
